# 播放页暗色环境背景与搜索相关性排序设计

**日期：** 2026-08-28
**范围：** 播放详情页背景与前景配色、本地歌单及媒体库列表内搜索
**状态：** 已与用户确认

## 目标

本次改动解决两个相互独立的问题：

1. 在不替换、不改写现有播放页模糊背景及其配置的前提下，新增一个参考飞牛音乐播放页的静态暗色多色环境背景方案。
2. 保留当前搜索的宽松匹配能力，同时建立明确的相关性分层，使标题严格命中的歌曲稳定排在字符穿插等模糊命中之前。

## 已确认决策

1. 新背景采用静态多色效果，不加入持续动画。
2. 新背景必须始终保持暗色，不直接照搬封面原始亮度。
3. 新背景启用时，播放页标题、歌词、翻译、罗马音、按钮、图标、进度条和状态栏统一使用白色体系。
4. 白色体系通过透明度区分信息层级，不混入当前主题色或用户自定义前景色。
5. 现有背景方案继续保留并作为默认方案；其所有配置和值保持原样。
6. 搜索继续允许 `sign` 这类模糊候选出现，但 `Sing` 等严格命中必须获得更高优先级。

## 非目标

- 不删除或重置现有 `theme.playDetail.background.*` 调节项。
- 不改变现有背景方案的视觉结果。
- 不为新背景增加动画、速度或运动幅度设置。
- 不移除字符穿插匹配，也不把搜索改成只返回严格匹配。
- 不调整在线音源服务端返回结果的排序；本次只处理应用本地列表搜索链路。

## 一、暗色环境背景

### 1. 方案选择与设置模型

在播放页背景设置中增加独立方案选择，提供：

- `现有模糊`
- `暗色环境`

新增一个只负责选择渲染方案的正式 setting：

```ts
'theme.playDetail.background.variant': 'blur' | 'ambientDark'
```

默认值为 `blur`，保证升级后的既有用户保持当前显示效果。

切换方案时只写入 `variant`。以下现有配置既不重置，也不被新方案复用或回写：

- `stretchScale`
- `blurRadius`
- `imageBrightness`
- `imageContrast`
- `maskMode`
- `maskColor`
- `colorMaskOpacity`
- `maskSaturation`
- `maskLightness`
- `vignetteColor`
- `vignetteSize`

切回 `blur` 后，现有模糊方案必须继续使用切换前保存的全部参数。

### 2. 设置界面行为

背景设置 Dialog 顶部增加二段式方案选择控件，并继续复用当前歌曲封面进行实时预览。

- 选择 `现有模糊`：显示当前全部模糊、蒙版与暗角参数。
- 选择 `暗色环境`：收起仅对旧方案有效的参数，只显示环境背景预览和简短状态说明。
- 切换过程只改变预览与方案键，不改变任何旧参数草稿或持久化值。

### 3. 颜色提取

基于现有封面颜色原生桥接能力扩展出多色提取接口。接口返回最多三组有代表性的封面颜色；提取过程应抑制以下样本：

- 近乎透明的像素。
- 极亮、接近纯白且缺少色相信息的像素。
- 极暗、无法贡献有效色彩关系的像素。
- 与已选颜色过于接近、不能形成第二或第三色的像素簇。

返回颜色不足三组时，使用已有颜色派生相邻色相；完全提取失败时，使用内置暗色中性调色板。失败不得导致背景空白或阻塞播放页渲染。

### 4. 暗色归一化

封面提取色不能直接用于背景。每组颜色进入渲染前都要经过暗色归一化：

1. 保留能够区分封面的主色相关系。
2. 将饱和度限制在适合长时间阅读的中低范围。
3. 将明度压入稳定的暗色范围。
4. 对极亮封面额外降低明度，确保白色前景始终具有足够对比度。

渲染层使用归一化后的三色生成全屏多段线性渐变，再叠加固定深色遮罩。效果目标是保留类似 `tests/飞牛音乐4.mhtml` 中左侧暗紫、右侧墨绿的环境色关系，但不显示可辨认的拉伸封面轮廓。

第一版使用静态渐变，不创建漂移色块、循环动画或定时器。

### 5. 渲染组件边界

现有 `PlayDetailBackgroundLayer` 继续只负责旧模糊方案。新增独立的暗色环境背景组件，职责包括：

- 接收归一化后的环境色。
- 绘制静态多段渐变。
- 叠加深色遮罩。
- 在没有封面或颜色提取失败时绘制内置暗色回退背景。

`PageContent` 根据 `variant` 选择背景组件，避免把两套渲染逻辑混入同一个组件并产生参数语义冲突。

设置页预览与正式播放页必须使用同一个暗色环境背景组件和同一套颜色归一化逻辑。

## 二、暗色环境方案的全白前景

### 1. 覆盖范围

当且仅当 `variant = ambientDark` 时，播放页前景调色板切换到专用白色组，覆盖：

- 顶部标题、返回按钮、更多按钮和状态栏图标。
- 歌曲名称、歌手、播放状态和时间文本。
- 播放、暂停、上一首、下一首、循环、音量等控制图标。
- 进度条轨道、缓冲进度、已播放进度、拖动预览和滑块。
- 当前歌词、未激活歌词、翻译歌词和罗马音歌词。
- 歌词跳转提示及播放页内设置弹层的相关前景元素。

状态栏继续使用透明背景和 `light-content`，与当前播放页强制浅色状态栏图标的行为保持一致。

### 2. 白色层级

所有颜色以白色为基础，只通过透明度表达层级：

- 主标题、主要控制、当前歌词：高不透明度白色。
- 歌手、时间、翻译和次要操作：中等不透明度白色。
- 未激活歌词、进度轨道和弱提示：低不透明度白色。

具体透明度由共享调色板统一定义，组件不得自行混入主题色。

### 3. 与现有自定义色共存

用户已保存的浅色组和深色组播放页自定义颜色保持原样。`ambientDark` 只在运行时提高专用白色调色板的优先级，不修改任何自定义色 setting。

切回 `blur` 后，播放页立即恢复现有的主题色或用户自定义前景色。

## 三、搜索相关性排序

### 1. 问题根因

当前本地列表搜索存在两个问题：

1. 候选过滤把 `sing` 转换为类似 `s.*i.*n.*g` 的字符穿插规则，因此 `sign` 也会进入候选集合。
2. 排序把歌名、歌手和专辑拼成一个长字符串，再与查询词计算编辑距离。标题为 `Sing` 的严格命中因此没有得到独立优先级，并会被长歌手名和专辑名稀释分数。

字符穿插匹配本身继续保留；本次修复重点是相关性排序。

### 2. 查询归一化

排序与匹配统一使用归一化查询：

- 裁剪首尾空白。
- 使用不区分大小写的比较。
- 保留查询内部有效字符和空格，不进行会改变歌曲语义的激进清洗。

空查询继续由现有页面逻辑处理，不进入排序函数。

### 3. 硬分层规则

每条候选结果先计算命中层级，再计算层内分数。层级优先级高于任何相似度分数：

1. **标题完全匹配**：归一化歌名与查询完全相等。
2. **标题前缀匹配**：歌名以完整查询开头。
3. **标题连续包含**：歌名包含连续查询文本。
4. **歌手连续包含**：歌手包含连续查询文本。
5. **专辑连续包含**：专辑包含连续查询文本。
6. **字符穿插模糊匹配**：仅满足现有宽松候选规则。

一条歌曲同时满足多个层级时，只采用最高层级。

这保证查询 `sing` 时：

- 标题为 `Sing` 的歌曲属于第一层。
- 标题为 `Sing It` 的歌曲属于第二层。
- 标题为 `Why We Sing` 的歌曲属于第三层。
- 标题为 `Sign` 的歌曲只属于第六层。

### 4. 层内排序

只在相同层级内比较相关性：

- 分别计算查询与歌名、歌手、专辑的相似度，不再构造拼接长字符串。
- 当前层对应字段的相似度拥有最高权重。
- 连续命中的位置越靠前，排序越靠前。
- 分数仍相同时保持原列表顺序，避免每次搜索出现无意义跳动。

实现可使用一次稳定排序或显式保留原始索引，不再依赖反转数组造成同分项顺序变化。

### 5. 结果范围

本次调整复用 `searchListMusic` 的所有现有调用方，因此同时作用于普通本地歌单和媒体库生成列表中的应用内搜索。

在线搜索页由外部音乐源返回结果，其服务端排序不在本次范围内。

## 四、数据流

### 暗色环境背景

1. 用户在背景设置中选择 `暗色环境`。
2. 应用只持久化新的 `variant` setting。
3. `PageContent` 获取当前封面并请求多色提取。
4. 颜色解析层过滤、补足并暗色归一化调色板。
5. 暗色环境背景组件绘制静态多色渐变与深色遮罩。
6. 播放页共享调色板检测到 `ambientDark`，为所有前景调用方返回白色体系。
7. 切回旧方案后，背景组件和前景调色板同时恢复原有逻辑。

### 搜索

1. 页面把裁剪后的查询和当前列表传给 `searchListMusic`。
2. 现有宽松规则产生候选集合。
3. 每个候选按字段计算最高命中层级。
4. 同层候选计算字段相似度、连续命中位置和原始索引。
5. 按层级、层内分数和原始索引返回稳定结果。

## 五、错误处理与回退

### 背景

- 无封面：直接使用内置暗色中性渐变。
- 原生多色提取接口不可用：使用已有主色相生成暗色派生调色板。
- 主色相接口也不可用或返回非法值：使用内置暗色中性渐变。
- 歌曲快速切换：取消或忽略上一首歌曲尚未完成的异步颜色结果，防止旧封面颜色覆盖新歌曲。
- 颜色数组包含非法值：过滤非法值并按不足三色规则补足。

### 搜索

- 缺少歌手或专辑：按空字符串处理，不影响标题层级。
- 查询包含正则特殊字符：继续转义后再构造宽松候选规则。
- 大小写不同：按同一归一化规则比较。
- 同层同分：保持原始列表顺序。

## 六、测试与验收

### 设置与兼容性测试

- setting 类型包含新的 `variant`。
- 默认值为 `blur`。
- 切换到 `ambientDark` 只更新 `variant`。
- 切回 `blur` 后十一项旧背景参数保持切换前的值。
- 旧版本缺少 `variant` 时按 `blur` 处理。

### 背景解析测试

- 三组有效颜色会被归一化为暗色调色板。
- 纯白、亮黄、高饱和红等亮色输入仍输出满足暗色约束的结果。
- 少于三色时可以稳定补足。
- 非法颜色、无封面和原生接口失败时使用预期回退。
- 设置预览与正式播放页引用同一背景组件和解析逻辑。

### 前景测试

- `ambientDark` 下共享调色板的所有播放页前景均基于白色。
- 主次层级只通过透明度区分。
- 状态栏使用 `light-content`。
- `blur` 下继续读取现有主题色和用户自定义色。
- 切换背景方案不会改写任何前景自定义 setting。

### 搜索排序测试

至少构造以下候选并验证查询 `sing` 的层级顺序：

1. `Sing`
2. `Sing It`
3. `Why We Sing`
4. 歌手字段包含 `sing`
5. 专辑字段包含 `sing`
6. `Sign`

同时覆盖：

- 查询 `Sing` 与 `sing` 得到相同层级结果。
- 严格标题命中不会被更高模糊相似度反超。
- 歌手与专辑不再通过拼接字符串稀释标题分数。
- 同层同分保持输入列表顺序。
- 正则特殊字符不会破坏搜索。

## 成果定义

完成后，用户可以在不丢失任何现有背景配置的情况下切换到静态暗色多色环境背景；该方案在任何封面下都保持适合白色内容阅读的暗色观感，播放页全部前景统一为白色体系。搜索 `sing` 时，`Sing` 等严格命中稳定排在 `Sign` 等模糊结果之前，同时仍保留现有宽松搜索的召回能力。
